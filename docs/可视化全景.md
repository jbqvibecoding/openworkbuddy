# 可视化全景

这个项目里**所有「把东西变成图」的路径**：界面自己画的图元、模型在正文里画的 SVG、真渲染器产出的
图表文件、把网页当画布截出来的设计稿、AI 生成的像素、终端里的图，以及它们各自的兜底、消毒和验收。

一句话总览：**前端一个图表库都没装**——界面上所有的条、柱、进度、缩略图都是手写 CSS；
真正的图表引擎（ECharts / Graphviz / mermaid / PlantUML）全部跑在**服务端或隐藏窗口里**，
产出的是能打开、能插进 PPT 和飞书文档的**文件**，不是页面上的一个组件。

---

## 0. 六条路，一张表

| 要画的东西 | 走哪条 | 渲染器 | 产出 |
|---|---|---|---|
| 界面上的进度/占比/趋势 | 原生 CSS 图元 | 无（手写） | DOM |
| 模型想在回答里配一张示意图 | 正文内联 `<svg>` | 浏览器 | 页面里的图卡，可存 SVG/PNG |
| 数据图表 / 架构图 / 流程图 / UML | `gen_diagram` 工具 | ECharts SSR、Graphviz WASM、mermaid、PlantUML | `<名字>.svg` + 2x `<名字>.png` |
| 小红书卡片 / 头图 / 分镜卡 | `html_to_image` | Electron 离屏窗口 | PNG（文字清晰，版式可控） |
| 有质感的画面 / 短视频 | `generate_image` / `generate_video` | 用户配的图像/视频模型 | PNG / MP4 |
| 节点关系、创作流程 | 无限画布 | JointJS + Dagre | 可交互的图，本地/远端存档 |

## 1. 界面自带的图元（零依赖，全是 CSS）

全仓库前端**没有引入任何图表库**（ECharts 只在 Node 侧 SSR 用）。所有可视化都是几个 div 加一行内联
`width` / `height` 百分比，因此天然跟主题、皮肤、深色模式一起变。

| 图元 | 位置 | 做法 |
|---|---|---|
| 7 日 tokens 柱状 | 账号 · 用量弹窗 | `.usage-bars .b{height:N%}`，hover 出具体数（`app-03.js:23,59`） |
| 7 日柱状（后台版） | 管理后台各用量页 | `bars7()`，柱高按 tokens 归一化，`title` 挂「N 次 · N tokens」（`admin.js:211-221`） |
| 进度条 | 后台席位/额度 | `progress(pct)`，≥80% 变黄、≥100% 变红——「席位只剩最后一个，一根纯色条是看不出来的」（`admin.js:194`） |
| 目标进度条 | Goal 目标卡 | `.gc-bar i{width:done/total}`，达成后整条转绿（`index.html:1414`） |
| 好评率条 | 评测页反馈汇总 | `.ev-bar i{width:upRate}`（`app-03.js:1348`） |
| KPI 卡片组 | 后台数据统计 | `kpi()` + `ui-stats` 网格（`admin.js:187`） |
| 徽章 / 状态点 | 通道状态、模型健康、任务运行中 | 一个 8px 圆点三态（灰/绿/红） |
| 缩略图 | 产出卡、附件 chip | 图直接 `<img>`；视频用 `<video src="#t=0.1">` 定格首帧；读不出来退回类型图标 |
| 等宽数字 | 耗时、计数、金额 | `font-variant-numeric: tabular-nums`——「数字在列表里逐行左右跳，是最廉价的一种糙」 |

## 2. 模型在正文里画的 SVG（`public/svgfig.js`）

模型直接在回答里吐 `<svg>`，界面**当图渲染而不是当代码贴出来**。单独成文件是为了能在 Electron 的真
Chromium 里跑 DOM 测试（`test/frontend.js:4425+`）。

### 2.1 流式补全
SVG 是一点点吐出来的。`repairPartialSvg()` 把半截内容切回最后一个完整标签，补上还开着的
`</style></svg>` 再渲染——于是**图会自己长出来**，而不是让人对着满屏尖括号干等。

角标分三态：还在吐字 = 闪烁的「绘制中」；停笔了但没闭合 = 一句实话「没画完」（不闪不转）；
正常收尾 = 什么都不说。回放历史时不会永远挂着「绘制中」在那儿闪。

### 2.2 消毒与作用域化（`sanitizeSvg`）
1. 砍掉 `script / foreignObject / iframe / object / embed / link / meta / audio / video / handler / animation`。
2. 删掉所有 `on*` 属性、`javascript:` / `data:text/html`、以及**任何指向外部的 href/src/url()**——
   外链图片和字体会把「用户看了这张图」这件事悄悄发出去。
3. 内联 `<svg><style>` 对整页生效，模型爱用 `.t` `.ts` 这种通名，所以每条规则都加上 `#svgfigN` 前缀锁死在这张图里。
4. 有 viewBox 就强制 `width:100%` 去掉 height，自适应列宽。

### 2.3 五个动作 + 看大图
`放大看 / 看源码 / 存矢量图 / 存图片 / 另存为…`（`svgfig.js:83-87`，处理在 `app-02.js:1699-1727`）：
- **存图片**：浏览器端把 SVG 转 PNG（`svgToPngDataUrl`，默认 **2 倍**）——转之前会把所有
  `var(--token)` 就地求值成真实色值、补上字体、垫白底，否则导出的图在别人电脑上是黑底黑字或整片空白。
- **另存为**：走系统保存框；网页端没有这能力就退回浏览器下载，并说明「想换地方去浏览器下载设置里改」。
- 默认保存落到**这次对话自己的成果文件夹**，不是工作区根目录。
- 按钮上闪一下「已存 ✓」再变回去——手指还停在按钮上，不能只靠 toast。
- **看大图**：全屏遮罩、滚轮缩放、按住拖动、百分比显示、Esc 退出（`app-02.js:1807+`）。

### 2.4 深色模式下也要能看
给模型准备了一套语义色变量，图里写 `var(--color-text-primary)` 而不是写死 `#333`：

```
--color-text-primary / -secondary / -tertiary
--color-border-primary / -secondary / -tertiary
--color-bg-subtle
```

浅色一套（`index.html:30-32`）、深色一套（`index.html:844-846`），名字沿用通行叫法，模型不用学新词。

## 3. `gen_diagram`：文本 → 图的渲染中枢（`diagram.js`）

五种输入，**统一产出 SVG**，环境允许再产出 PNG（飞书/Word 只收 PNG/JPG）：

| kind | 渲染器 | 离线？ | 备注 |
|---|---|---|---|
| `echarts` | ECharts 官方 SSR `renderToSVGString` | ✅ 纯 Node | option 收 JSON 或 JS 字面量（模型爱写后者），字面量在**无权限 vm 沙箱**里求值，2s 超时 |
| `dot` | `@viz-js/viz`（Graphviz 的 WASM 编译） | ✅ 纯 Node | 架构图/依赖图首选 |
| `mermaid` | Electron 隐藏窗口离线渲染 | ⚠️ 桌面版 | 纯 node 起服务时降级到 kroki 在线 |
| `plantuml` | 本机 `plantuml` → 配置的 server → kroki | ⚠️ 三级尝试 | 自带 PlantUML 的 deflate + 私有 base64 字母表编码 |
| `svg` | 直传校验 | ✅ | 只做校验 + 转 PNG |

离线可靠度排序写进了技能里：`echarts = dot（纯本地）＞ mermaid（应用内）＞ plantuml（可能要联网）`。

### 3.1 SVG → PNG 的三级兜底（`svgToPngAnyhow`）
1. **Electron 隐藏窗口**：按 SVG 尺寸开窗、`setZoomFactor(2)`、等 `document.fonts.ready`、再等一帧合成
   （offscreen 下截早了是白图）、`capturePage().toPNG()`。
2. **本机 Chrome 无头**：写临时 HTML，`--headless --force-device-scale-factor=2 --screenshot`。
3. 都没有 → 只交付 SVG，并在 note 里说清楚原因，不假装成功。

### 3.2 mermaid 的配色与字体
mermaid 自带的 default 主题是一套高饱和粉/黄/紫/绿，贴进正经报告里很跳，所以在渲染前统一换成一套克制的
`themeVariables`；字体也必须写死（mermaid 默认 `trebuchet ms`，中文只能靠浏览器兜底）（`browser-render.js:57-95`）。

### 3.3 mermaid 语法自动纠错（`repairMermaid`）
本机 176 段会话里 `gen_diagram` 调了 37 次挂了 7 次（18.9%），**七次全是 mermaid 语法错**，且全落在四类
纯机械的写法问题上。所以挂了先替它改对再渲一次，只碰这四类，改完没变化就照旧报错，**绝不猜一张别的图出来**：

| 错法 | 例子 | 修法 |
|---|---|---|
| 标签开 `["` 收 `")` | `F["…(将入iOS)")` | 按开头补对收尾括号，引号里一个字不动 |
| subgraph 标题带括号/冒号没加引号 | `subgraph 上游: 卖什么` | 补引号 |
| timeline 用全角「：」当分隔符 | `2024： 进出口 42 亿` | 换半角，正文里原有的半角冒号反转成全角 |
| gitGraph 中文分支名没加引号 | `branch 冷启动P0` | 补引号 |

报错也重写过：mermaid 只说 `Parse error on line 7 … Expecting 'SQE'`，模型读不懂是哪个字符，只能整张图
重写碰运气。现在把**出错那几行的原文**贴出来，并附一句「只改这几行，别整张图重写」（`diagram.js:262-275`）。

### 3.4 图怎么进交付物
- **PPT**：数据图表用 pptxgenjs 的 **原生 `addChart`**（在 PPT 里可继续编辑，不截图不画表格凑数）；
  流程/架构/时序先 `gen_diagram` 出 PNG 再 `addImage`（`skills/ppt-design/skill.md:77-95`）。
- **飞书文档 / Word**：markdown 里独占一行写 `![图说明](名字.png)` 即真插图。
- **Excel**：exceljs 不支持原生图表，如实退回「输出整洁的透视汇总表」，不糊弄。
- **交互式大图表**：单文件 HTML + ECharts CDN，适合仪表盘类交付（但要先问清「这页要联网用吗」）。

## 4. 把网页当画布：`html_to_image`（`htmlshot.js`）

自媒体图文最顺手的生产方式是「模型写 HTML 排版 → 截成图」——HTML 是模型最擅长的排版语言，
比让图像模型画带字的图靠谱得多（文字不糊、版式可精确控制）。

- Electron **离屏窗口**渲染，不会闪出来打扰用户；**串行队列**，批量出卡片时排队一张张来（同时开一堆会吃爆内存）。
- 常用画布尺寸写在工具描述里：小红书 3:4 = 1242×1656、公众号头图 2.35:1 = 1200×511、视频封面 16:9 = 1920×1080。
- `full_page` 按内容实际高度整页截（长图/万字长文）；`wait_ms` 给网络字体和大图留时间。
- 纯 node 起服务时没有 Electron，直接报人话错误让用户换桌面版，不静默失败。

**两条路的选择被写成了产品纪律**：`html_to_image`（设计稿，字清晰）和 `generate_image`（AI 作画，有质感）
成品差别大到会返工，所以用户没点名时**先 `ask_user` 把两条路摆出来问一句**；用户点了名就照做，
不许拿「字会糊」当理由偷偷换成另一条（`tools.js:428-495`、`skills/xhs-cards/skill.md`）。

### 网页本身的视觉质量
- `web-styles` 技能：动笔前先从八个视觉方向里挑一个，把结论写进开场白一句话。跳过这步「只会调出一张涂了新颜色的旧脸」。
- `html-page` 技能硬规范：单文件内联、响应式（页面绝不允许横向滚动）、**深浅色都要能看**（CSS 变量 + `prefers-color-scheme`）、
  不许出现 Lorem ipsum 占位符、不引用不存在的本地图片。
- `check_page` 工具：静态体检（DOCTYPE/viewport/标题/标签闭合/外链资源/本地引用是否存在/正文是否空壳）
  **+ 真浏览器打开一遍**，做完的网页要过这一关才算交付。

## 5. AI 生成的像素（`media-models.js` + `tools.js`）

五路能力：`vision / image / video / tts / asr`，配置拆成两张表——

```
config.providers    = [{ id, name, kind, base_url, api_key }]      一把 Key 一行
config.media_models = [{ id, cap, name, provider, model, voice }]  一个模型一行，只引用渠道
```

一把 OpenRouter 的 Key 能同时喂图、视频、视觉，不用抄四遍（换 Key 时漏一处就是半年后突然 401）。
渠道 kind 覆盖火山方舟 / 阿里云百炼 / OpenAI / OpenRouter / 硅基流动等。

- **`generate_image`**：支持 `reference_images`（最多 4 张）保持角色/商品/画风一致——
  「光靠文字描述同一个角色，跨镜头一定长得不一样」；渠道不支持参考图时明确报错，不偷偷退回纯文生。
  同名同参数会复用上次产物不再花钱，`no_cache` 强制重生。
- **`generate_video`**：给 `first_frame` 是图生视频，首尾都给是「从这张变到那张」；型号对不上在发请求**之前**就报错，不白花钱。
- **`look_at_image`**：视觉模型读图（截图、图里的字），必须带具体问题。
- 生图/视频/语音/看图是开箱向导的第三步，按需开通，都不填也不影响办公。

## 6. 无限画布：图结构的可视化（`app-07-canvas.js`）

- **JointJS** 负责画布/节点/连线交互，节点是普通 DOM（因此主题、字体、无障碍跟工作台完全一致）。
- **Dagre** 做自动排版：`rankdir:LR, ranker:network-simplex, acyclicer:greedy`，按**真实连线**算紧凑有向图，
  排完自动居中适应（`canvasAutoLayout`，`app-07-canvas.js:200-220`）。排版期间静音历史记录，避免把一次排版拆成 N 步撤销。
- 两个库都从 `node_modules` 原样提供（`/vendor/joint/`、`/vendor/dagre/`），**不复制不改写源码**，
  开发态、桌面包、离线模式用的是同一份文件，LICENSE 一并暴露。
- 12 类节点分 5 组，连线的语义是「这个输入喂给下一个创作步骤」；缩放 / 平移 / 框选 / 灯箱预览 / 右键菜单见
  [UI 交互全景 § 8](UI交互全景.md)。

## 7. 终端里的可视化

| 模块 | 干什么 |
|---|---|
| `term-image.js` | 把产出的图**直接画在终端里**。两种协议：**kitty**（kitty / Ghostty，载荷切 4096 字节块）和 **iTerm2 内联图**（iTerm2 / WezTerm / mintty / 手动开关的 VS Code）。 |
| `md-tty.js` | 终端里的流式 Markdown：按行缓冲，半行里只要还有没闭合的 `**` / 反引号 / `[` 就留到下一片——「错着吐出去就再也收不回来了」。非 TTY 时一个字节都不改（`> 答案.md`、`\| pbcopy`、`--json` 要拿原始 Markdown）。 |
| `cli.js` 的 `drawOutputs` | 每轮跑完挑最多 3 张图贴出来；SVG 先用 `svgToPngAnyhow` 栅格化（终端协议只收位图），转不动就安静跳过。宽度按终端列宽算，留两列边距。 |

**宁可不画也不能画错**是这里的第一原则：协议不支持时那串转义序列会变成满屏 base64 乱码，比没有还糟。
所以只认白名单里确认支持的终端；**tmux / screen 里一律不画**（要额外的 passthrough 配置）；
VS Code 要用户自己开 `terminal.integrated.enableImages`，探不到就不发，只给一行提示告诉他开哪个开关。
强制开关：`OPENWORKBUDDY_TERM_IMAGES=1|0`。

没画出来的图会给一条**真能粘到 shell 里跑的命令**（交互模式里则是 `/open 名字`），而不是一句
「用系统默认程序打开」——那等于没说。

## 8. 桌面宠物：两套渲染

- **内置猫**：手写 SVG，分层（尾巴、耳朵、两套眼型、爪子、笔记本），随机眨眼、走动、气泡、光环、特效全用 CSS 类名切换（`pet.html`）。
- **精灵图**：直接吃 Codex / Petdex 的公开格式，不自己造轮子——`~/.codex/pets/<slug>/` 下
  `pet.json` + `spritesheet.webp|png`，**8 列 × 9 行，单帧 192×208，整图 1536×1872**，行序是格式的一部分不能猜；
  ChatGPT 导出的 11 行版本忽略多出来的两行。canvas 按行列裁帧播放（`pet-sprites.js`）。
- **用户照片**：第三种形象，圆形裁切 + 光环。
- 刻意不引任何图像库：只需要读出宽高校验，PNG/WebP 文件头自己解就够了。

## 9. 设计系统与配色（`public/css/ui.css`）

搬的是 shadcn/ui 可移植的那两层，**不搬 React/Tailwind**（那会毁掉「clone 下来双击就能跑」这个性质）：

1. **令牌契约**：`background / foreground / muted / border / ring / radius` 这套名字和语义与 shadcn v4 一字不差，
   `--wb-*` 全部指向它们，颜色只有这一个真源。
2. **组件几何**：按钮高 36 / 圆角 8 / 字号 14 / 图标 16 / focus 3px ring，全部照抄 shadcn 的数值。
   行内控件的高度只在一处定（`--wb-ctl-h: 36px` / `sm: 30px`）——以前一条工具栏上四种底边，10 行里 9 行不齐，最大差 5px。

**圆角阶梯**：以 10px 为基准每档差 2px 共七档（4/6/8/10/12/14/999）。之前内联样式里写死过 29 个不同圆角，
「挨着的两个控件差 1px 谁也看不出是设计，只看得出没对齐」。

**颜色纪律**（贯穿全仓库）：
- 填充色和文字色分开：同一个紫/红，当背景够用，当文字在浅底上不够 → 另给 `--brand-text / --danger-text / --success-text / --warning`，每档都标注了实测对比度。
- 选中态不拿品牌色当文字：品牌紫压自己的浅紫底只有 4.86，比未选中项还低，层级是反的 → 文字用 `accent-foreground`，品牌色退回去当左侧 3px 指示条。
- 深色模式下不许写死浅色底：`color-mix(in srgb, var(--success) 14%, transparent)` 叠在当前表面上，两套主题各自成立。
- **图表配色规范**写进了技能：一张图 ≤4 色，统一用 `#5b5ff7 #8b5cf6 #22c55e #f59e0b #ef4444`；标题直接写洞察
  （「Q3 华东区销量领先」而非「销量图」）；数字千分位；坐标轴带单位；文字 ≥11px（`skills/data-viz/skill.md`）。

## 10. 图标与品牌图形

- **lucide**（ISC）以**内联 sprite** 形式随页面走，不联网、能跟着 `currentColor` 变色；取图标只有一个入口 `ic(name)`。
- `icons.js` 反过来**从 sprite 解析图标名清单**当服务端的真源——头像存的是 `"rocket"` 这种图标名，
  「再在代码里抄一份清单迟早会跟 sprite 对不上」。读不到 sprite 就退回「文字 / 上传图片」两条老路，不把登录一起带崩。
- 头像三类候选（猫标 / 图标 / emoji）统一到等大方格网格里。曾经的 bug 很典型：`.ava-ic` 用 `62%` 量自己，
  而行内元素没有宽度，百分比找不到参照物，浏览器退回 SVG 默认的 300×150 —— 每个候选都有巴掌大。
- 应用图标由 `scripts/genlogo.py` 生成：外框是**真·超椭圆**（n=5）而不是 CSS 圆角矩形——
  圆角矩形曲率跳变，放大能看出接缝；超椭圆曲率连续。SVG 没有超椭圆图元，用自适应折线逼近，
  实测最大偏差 ~0.1px（1024 画布）。猫标在界面里作为 `#wb-cat` symbol 复用，圆形容器里按 82% 缩放
  （实测 100% 时耳朵尖有 5.3%–12.4% 的像素被圆切掉）。

## 13. 几条反复出现的规矩

1. **图要么真渲染，要么不画**：不手写 SVG 坐标（「一画就崩」），画图一律走 gen_diagram。
2. **兜底必须说人话**：转不了 PNG 就说「本环境无法转 PNG，已交付 SVG」并给条件，不假装成功也不静默失败。
3. **宁可不画也不能画错**：终端图形协议不确定就不发；模型的 SVG 没闭合就说「没画完」，不永远闪「绘制中」。
4. **导出要脱离现场**：`var()` 求值、字体内联、垫白底——图离开这个页面之后仍然要对。
5. **外链一律砍掉**：内联 SVG 里的外部图片/字体会把「用户看了这张图」发出去。
6. **两条成品路线必须先问**：html_to_image 与 generate_image 差别大到会返工，不替用户偷偷决定。
7. **深浅两套都得成立**：所有颜色走令牌 + 语义变量，且有测试盯着对比度。
